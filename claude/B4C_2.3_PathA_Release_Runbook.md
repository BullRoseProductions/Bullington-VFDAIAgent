# B4C — 2.3 Path A presence decision + how 13–18 reach phones

> **Corrected Oct 20.** An earlier version of this doc pitched a Capgo OTA "quick win" to push releases onto phones without a store review. That was wrong — the Capgo code was wired in but never set up: Ashlea confirmed on capgo.app there's no login and no API key, so no account was ever created and the OTA path isn't real for us. (The stray `.capgo-credentials` folder on the Mac is just leftover install scaffolding, not an account.) **Phones update via store builds.** The build mechanics now live in their own doc: [[B4C_3.1_StoreBuild_Runbook]]. What's left here is the presence decision this release rides on.

## The decision (Ashlea, Oct 20): Path A

Presence stays **Path A — geofence-only**, the clean "we never track you" promise. Path B (continuous motion) is deferred to a later per-department opt-in, and only after the Transistorsoft vendor question. So this release carries the web features to phones with **no native/presence change, no new permissions, no privacy-label change.** Fork doc: [[B4C_iOS_Presence_Privacy_vs_Reliability_Fork]].

Confirmed in the repo: `src/geofence.js` is Path A — motion off (`disableMotionActivityUpdates: true`), persist `GEOFENCE`, `startGeofences()` not `start()`, no `server.url`. Byte-identical through `207f888`. The 3.1 build must keep it that way.

## What's shipping

Releases 13–18 (probation, qualifications, scroll restore, expirations, readiness scorecard, onboarding item-config) — all JS/web, already web-live on `main` (`207f888`) but web-only on phones. The DB security fixes (apparatus, apparatus_maintenance, members cross-dept, admin-gate `f040899`) are **already live on web AND native** — DB policies go live the moment they're applied, no build needed. So the 3.1 build is purely about getting the **UI layer** onto installed apps.

## How they reach phones

A normal store build, versioned 3.1 (iOS build 14, Android versionCode 12), submitted to App Store Connect and Play Console. Path A means nothing about location/permissions changed, so a routine review. Full step-by-step — including the one-time Capgo-removal cleanup that rides along — is in [[B4C_3.1_StoreBuild_Runbook]].

**Built ≠ live:** nothing is "on phones" until the store build is Approved and members update. Store review takes days; adoption is partial and trickles in. The truth doc flips the native column only then.

## Deferred (not this release)
- **Path B (per-department opt-in to continuous motion)** — its own project; first step is the Transistorsoft question (is there any iOS mode that improves reliability without continuous acquisition?). Until then, Path A's correction net (early-catch, one-tap officer fixes, QR at the door) is the iPhone story.
- **The 2.3 visual-refresh follow-ups** (Training internals, Settings/Funding sub-screens) — cosmetic, already on-brand; not blocking this release.
- **A real OTA service** — not adopted. If update speed ever becomes a real pain, that's a fresh evaluation of a service with an account and a backend, not the dead Capgo wiring.

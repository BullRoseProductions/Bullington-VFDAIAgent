## Minor notes (none gate-blocking)
1. **Reopen leaves `doc_checked_*` stale.** Unticking a signed doc-item via `set_onboarding_item` (allowed by design — reopening ≠ signing) clears `done`/`checked_*` but not `doc_checked_*`; it's not read while `done=false` and is overwritten on re-sign. Internal only, never surfaced. Optional tidy-up: null `doc_checked_*` on untick.
2. **Any leader can reopen a configured item**, not just its approver — by design: reopening can't create a false positive, only the right approver (or DA) can re-sign. The approver model governs *completing*, not *reopening*. Worth knowing; not a hole.
3. **A person-approver member can't be hard-deleted until the item is re-pointed** (FK has no ON DELETE; the shape CHECK forbids SET NULL). B4C uses soft `member_separation` anyway.
4. **probation RETEST 56/0/5** after this migration is CC's reported re-run; I verified the structural reasons it holds (the `satisfied` logic is byte-identical and `probation_status` text is asserted unchanged) rather than re-running it.

## Part 1 — what it does

1. `REVOKE ALL … FROM anon` on the 56 relations + `training_session_audit_seq_seq` (446 live ACL privilege entries).
2. `ALTER POLICY "<name>" ON public.<tbl> TO authenticated` × 19. **ALTER POLICY … TO changes the roles only** — the USING / WITH CHECK
   expressions are never re-entered, so the predicates cannot drift by construction; the proof below checks it anyway, byte for byte.
3. F-3, forward-only:
   - `ALTER DEFAULT PRIVILEGES FOR ROLE postgres IN SCHEMA public REVOKE ALL ON TABLES / ALL ON SEQUENCES / EXECUTE ON FUNCTIONS FROM anon`
   - `ALTER DEFAULT PRIVILEGES FOR ROLE postgres REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC` — **⚑ global, by necessity**: PUBLIC's
     EXECUTE is Postgres's built-in global default, and a per-schema REVOKE cannot remove it. Effect: functions **postgres creates
     from now on, in any schema**, no longer get PUBLIC EXECUTE. In `public` they still get `authenticated` + `service_role`
     (the per-schema defaults stay). Existing functions are untouched (dry run: `is_leader`'s ACL still carries `=X`). This makes the
     "REVOKE FROM anon, public" step in new SECURITY DEFINER migrations belt-and-braces rather than load-bearing — keep writing it.
4. Nothing else. Not touched: `supabase_admin`'s defaults (the platform's), postgres's defaults in `storage` (out of scope), any
   function body, any predicate, any authenticated / service_role grant.

### Preflight (refuses, changes nothing)
- the anon grant set = the pinned map, privilege by privilege, all 57 objects (MAINTAIN compared out — PG17-only; REVOKE ALL removes it anyway)
- each of the 19 policies = its md5 pin over table | name | cmd | permissive | roles | USING | WITH CHECK; exactly 19 `{public}` policies
- authenticated's and service_role's full privilege matrices = md5 pins
- every public object owned by postgres (else the default-privileges fix wouldn't cover it)
- refuses if already applied

### In-transaction proof (any miss → RAISE → everything rolls back)
- **Row counts as real people (the load-bearing one):** for EVERY department, a real Department Admin and a real plain member
  (Active, unique email, not separated) — `SET LOCAL ROLE authenticated` + their JWT email claim — count every one of the 56 relations
  BEFORE and AFTER. Must be identical, errors included (`E:<sqlstate>`).
- the 19 policies: roles `{authenticated}` and md5(USING | WITH CHECK) = the pinned predicate md5; no `{public}`/`{anon}` policy left in public
- anon (and PUBLIC) hold no ACL entry on any public relation or sequence; `SET ROLE anon` is refused (42501) on all 56
- authenticated's / service_role's matrices unchanged; public policy count and function count unchanged
- default ACLs: postgres/public grants anon nothing; postgres's global function default exists with no PUBLIC entry
- `verified` presence count unchanged
- then `NOTIFY pgrst, 'reload schema'` and a state row

### RETEST (rolled back — SENTINEL per department)
O1 anon holds nothing / no {public} policy · O2 the 19 predicates byte-identical, TO authenticated · O3 matrices + defaults ·
per department: T1 real DA + member reads identical with the 19 policies TO authenticated vs temporarily back TO public ·
T2 anon refused on all 56 · T3 station_presence byte-identical, verified unchanged.
*Honest note:* T1 is close to tautological (authenticated is a member of PUBLIC, so the flip cannot narrow an authenticated read).
The proof with teeth is the migration's own before/after real-person counts plus the predicate md5s.
